I completed a GSM8K worksheet benchmark on a Tesla T4 using Qwen2.5-1.5B-Instruct in FP16 through vLLM. It compares latest-only worksheets with naive appending across ten single-number updates, with stable IDs and an unchanged target. All 66 requests completed (three repetitions per condition and version), with prefix caching disabled. At edit 10, naive append uses 16,748 versus 1,591 input tokens (10.53x); mean engine latency is 81.573s versus 10.130s (8.053x). Output lengths differ, so latency includes a decoding confound. Raw CSVs, plots, dependency versions, correctness results and the report are saved. The single GPU session was stopped. PatchKV is not implemented or evaluated, and no PatchKV speedup is claimed.
